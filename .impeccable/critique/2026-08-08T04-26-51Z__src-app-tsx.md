# Anti-Patterns Verdict

**LLM assessment**: This does not read as AI slop; the failure mode is an unfinished power tool. The board metaphor (income above / expenses below a month spine, proportional card heights, cumulative balance wedge) is original product design. Trust collapses on details instead: emoji category icons in a monochrome shadcn UI, 8–11px text carrying the core numbers, "Chart Scale (px per $1000)" as a user-facing setting, and math that is visibly wrong in anonymous mode.

**Deterministic scan**: unavailable. `detect.mjs` crashed after a real attempt (`Error: bundled detector not found`, exit 1); the engine file `detect-antipatterns.mjs` is absent from every candidate path in the skill install. Zero automated findings; no false positives to classify.

**Visual overlays**: no user-visible overlay available. Script injection into the live page succeeded (mutation preflight passed), but the overlay server returned 404 for detect.js (same missing engine). Fallback signal: manual screenshot + accessibility-tree evidence, which independently confirmed the hover-only add buttons, unnamed icon buttons, and empty-state problems.

# Overall Impression

A genuinely original visualization wrapped around an untrustworthy core loop. The one thing this product promises, a believable future balance, is wrong in anonymous mode and visually broken by any large item. Fix trust first; the aesthetic register (calm, precise, Linear/Stripe) is already close.

# What's Working

1. The board metaphor is real product design: the income/expense split around a horizontal month spine, proportional heights, and the SVG balance wedge that correctly crosses from gray to red at zero.
2. The Record Entry disclosure pattern: a plan summary card expanding into an inline editor, expected amount pre-filled, so reconciling takes two clicks. This embodies "fast to confirm."
3. Correct micro-decisions: expected pre-fills actual, one-time plans auto-complete when recorded, copy-link flips to a checkmark.

# Priority Issues

1. **[P0] Anonymous-mode running balance ignores recorded one-time actuals.** `addLocalEntry` (src/lib/local-storage.ts:172) marks one-time plans completed; `calculateLocalBalances` (src/pages/anonymous-app.tsx:88) then drops them from the cumulative math. Verified live: a $25,000 recorded expense left every future month unchanged. The mode meant to sell the tool shows wrong math. Fix: delete the duplicated calculator and reuse `calculateBalances` from src/lib/calculations.ts.
2. **[P0] The month spine breaks alignment under a large item.** The center band sits in normal flex flow (src/components/month-column.tsx:254), so one tall card dislocates that column's band and the card runs off-viewport. Fix: fixed-y band across columns plus capped card height or auto-fit scale.
3. **[P1] Destructive delete with no confirmation and no undo.** add-item-modal.tsx:516 cascade-deletes a plan and all its entries in one click. Fix: scoped confirm ("Delete 'Monthly Salary' and its 3 recorded entries?") plus undo toast.
4. **[P1] Primary actions are hover-gated; the empty state teaches nothing.** `+ Income` / `+ Spend` render only on hover (month-column.tsx:243, 324): invisible to first-timers, dead on touch, unreachable by keyboard. Browser evidence confirmed the empty board offers no visible action at all. Fix: always-visible muted add buttons plus one anchored prompt in the current month.
5. **[P1] No mutation feedback, and public links grant full edit.** Invites/saves/imports report nothing (`onError: console.error`, src/App.tsx:219); sharing gives any link holder edit and delete over the owner's data with no read-only option. Fix: toast layer for outcomes; view-only public links by default.

# Persona Red Flags

**Jordan (first-timer, anonymous)**: 12 empty columns, zero clickable-looking actions in the first 5 seconds; "New Plan / (exp) / Record entry now" jargon in the first modal; three names for two actions ("Record Entry" / "Record Payment" / "Save Plan"); header "Balance: $0" misreads as current balance.

**Sam (accessibility-dependent)**: unnamed icon buttons (prev/next/settings verified nameless in the a11y tree); selects with visual-only labels; PointerSensor-only drag with no KeyboardSensor; ~2:1 contrast on 9px expected amounts; hardcoded light-mode RGB card colors that break in dark mode; emoji-only debt warning.

**Riley (stress tester)**: $25k expense reproduces both P0s; long names truncate to stubs even in kilopixel-tall cards; overlay click silently discards a filled form; balance wedge floods columns at realistic balances; authenticated user with zero cashflows may skeleton-load forever (src/App.tsx:250).

**Priya (invitee, not finance-minded)**: full edit powers over someone else's budget from a "view" link, including settings; no legend to answer "are they okay this month?"; the only CTA aims to convert her, not help her read.

**Ana (anonymous visitor deciding whether to sign up)**: the amber save-banner is the loudest element before she has data; her natural first test (plan a big purchase) hits the wrong-math P0; "Save to Account" bounces to OAuth with no explanation of what happens to local data.

# Questions to Consider

1. If the delta is the product, why is it the smallest, faintest text on screen? What would a first-class delta glyph per month look like?
2. Should proportional card height survive real data, or is capped height + a different amount encoding (log scale, width, intensity) the honest answer?
3. Why does anonymous mode have its own balance calculator at all?
4. Is "public link = full edit" a feature or an accident? What is the view/comment/edit story?
5. Reconciliation is the product's heartbeat; is a silent outline-to-solid style swap enough of an event?
